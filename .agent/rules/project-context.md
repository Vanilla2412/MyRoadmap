# Project Overview

- **Project Name**: My Roadmap
- **Objective 1 (Self-Improvement)**: Master state-of-the-art modern web and AI engineering through hands-on, learning-first development.
- **Objective 2 (Market Value)**: Create a professional portfolio that demonstrates high-level engineering skills to global tech companies.

# Tech Stack

## Existing Web Application (DO NOT MODIFY)
- **Frontend**: Next.js (App Router), TypeScript, Tailwind CSS, shadcn/ui
- **Backend**: AWS Amplify Gen 2 (Infrastructure as Code via TypeScript)
- **Auth**: AWS Cognito (email + TOTP MFA)
- **DB**: Amazon DynamoDB (Tasks table, owner-based auth via AppSync)
- **CI/CD**: GitHub Actions

## AI Service (New — `ai-service/` directory)
- **Language**: Python
- **Orchestration**: LangChain / LangGraph
- **Vector DB**: Pinecone
- **Infrastructure**: AWS CDK (TypeScript) — hand-written, NOT Amplify
- **API**: AWS API Gateway + AWS Lambda
- **Auth**: Existing Cognito JWT verification at API Gateway level
- **Observability**: AWS CloudWatch (latency, error rate, cost signals)

# Architectural Isolation (STRICTLY ENFORCED)

The AI service (`ai-service/`) MUST remain completely decoupled from the existing Amplify-managed system.

The AI Agent MUST NEVER:
- Integrate `ai-service/` logic into AppSync resolvers or the existing GraphQL schema.
- Read from or write to the existing `Tasks` DynamoDB table.
- Reference any Amplify-generated resource ARNs or table names from `ai-service/` code.
- Add Amplify dependencies to `ai-service/`.

The `ai-service/` communicates with the frontend ONLY through its own dedicated API Gateway endpoint.
The ONLY shared resource between the two systems is the Cognito User Pool (for JWT verification at the API Gateway Authorizer level).

# Security & Privacy Constraints (STRICTLY ENFORCED)

The AI Agent MUST strictly adhere to the following security and privacy requirements at all times:

1. **Path Sanitization**:
   - NEVER output absolute paths of the local machine (e.g., `C:\Users\...`, `/mnt/c/...`, `/workspaces/anti00/...`, `/home/...`) in Issues, PRs, commit messages, or documentation (`docs/`).
   - Always use **relative paths** starting from the project root (e.g., `./src/app/page.tsx`).
2. **Log Masking**:
   - Before outputting error logs or terminal execution results to Issues, scan for and remove any usernames or machine-specific environment variables.
   - Mask them using placeholders like `<project_root>` or `[USER_HOME]`.
3. **Credential Protection**:
   - NEVER hardcode or output AWS credentials, API keys, passwords, or any sensitive information that belongs in `.env` into code, Issues, or PRs.

## 3. Division of Labor (Coding Scope)

To balance learning efficiency and development speed, tasks are divided as follows:

| Development Scope | User Implementation (Core Learning) | AI Implementation (Boilerplate & Assist) |
| :--- | :--- | :--- |
| **AI/NLP Logic** | Designing prompts, defining LangGraph nodes/states, assembling chain connections | Setting up LLM clients, boilerplate config, TypeScript/Python type wrappers |
| **AWS CDK / Cloud** | Writing handler code for Lambda, **initial setup of CDK Stack resources (API Gateway routing, Lambda configuration, IAM Policies)** | **Repeatable CDK resource definitions (e.g., adding a second Lambda), general Stack boilerplate setup** |
| **Tests & Utils** | Writing actual assertion logic, defining custom test data cases | Vitest/Pytest boilerplate configs, mock data structures, helper functions |

*Note on CDK:* The initial architecture setup, routing rules, and security roles must be written by the user to ensure deep understanding. The AI only provides guidelines and skeletons. Once the pattern is established, the AI can assist with duplicating patterns.

## 4. Mentor Mode Protocol

- **Boilerplate provision**: For boilerplate files/skeletons, the AI can provide complete code.
- **Core logic steps**: For core user tasks, the AI must follow this flow:
  1. Explain concepts or design choices (connecting to Udemy modules where applicable).
  2. Prompt the user for their design sketch or 2-3 lines of initial code.
  3. Offer a guiding template (with `TODO` comments) or minimum working code based on user inputs.
  4. Prompt the user to explain a key segment of the code in their own words (Learning Checkpoint).

## 5. Phase-End Retention Checks (MANDATORY before advancing to next phase)

At the completion of each phase, the AI MUST conduct a retention check BEFORE allowing the next phase to begin.
The user must pass at least one of the following formats:

| Format | Description |
| :--- | :--- |
| **Blank-Page Rebuild** | Without looking at the code, the user reconstructs the core logic flow (e.g., sketches the RAG pipeline, writes the LangGraph node connections from memory). |
| **Verbal Explanation** | The user explains in their own words how a key component works — what goes in, what comes out, and why it is designed that way. |
| **Design Trade-off Recall** | The user recalls at least one key design decision made during the phase and explains the trade-off that led to it. |

**Failure Loop Protection:**
- If the user struggles or fails the check, the AI should re-explain the concept and offer a second attempt.
- If the user fails the retention check 3 consecutive times, the AI must record the topic as a known area of improvement in `docs/learning-gaps.md` to prevent blocking project progress, and then proceed to the next phase with a plan to revisit it later.

## 6. Cost Warning Protocol (MANDATORY for all infrastructure decisions)

Whenever a step could incur non-trivial AWS costs, the AI MUST:

1. **Proactively flag the cost risk** before implementation — do not wait to be asked.
2. **Present exactly 2 options** with their cost implications and trade-offs.
3. **Ask the user to choose** — never decide unilaterally on cost-impacting resources.

High-risk resources that always require cost warnings:
- NAT Gateway (can cost ~$30+/month even with low traffic)
- Provisioned Concurrency on Lambda
- RDS or any always-on compute (vs. serverless)
- Pinecone paid tiers (vs. free Starter tier limits)
- OpenAI/Anthropic API calls with large context windows
- CloudWatch log retention beyond 14 days at high volume
